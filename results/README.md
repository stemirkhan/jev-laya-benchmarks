# Сохраненные результаты

Здесь опубликована проверенная проекция результатов эксперимента 27 сентября 2026 года. Числа, ID документов, оценки и порядок выдачи сохранены без округления. Это производные файлы из исходных журналов; оригиналы остаются в частном архиве.

Все JSONL сжаты gzip. В архиве нет текстов запросов и документов: ID относятся к официальным наборам BEIR SciFact, FiQA и NFCorpus.

| Файл в `data/` | Содержимое |
| --- | --- |
| `main/<model>.jsonl.gz` | Пять моделей: по 2542 измеренных списка и два списка прогрева. Для каждого списка - dataset, method, query_id, phase, attempt, время в секундах, 20 ID документов с исходным/новым рангом и точной оценкой; для GPU также пики памяти в байтах. |
| `candidates/<dataset>.<split>.<method>.jsonl.gz` | Общие кандидаты BM25/RRF для pilot и test: ID, ранг и исходная оценка. |
| `quality.json.gz` | Метрики по каждому запросу и их средние для исходной выдачи, oracle и всех пяти моделей; 30 парных bootstrap-интервалов; полнота и счетчики ошибок; SHA-256 использованных test qrels. |
| `model-settings.json` | Фактические ревизии, точность, размер пакета, инструкции, ограничения длины, параметры API и общие характеристики GPU. |
| `memory.json` | Максимальные пики allocated/reserved CUDA memory по измеренным спискам основного теста. |
| `throughput.json` | Три прохода по 480 пар на модель, прогрев и загрузка; отдельная RTX 5090 с прежними настройками, без повторной оценки test-качества. |
| `api-cost.json` | Usage и стоимость OpenRouter отдельно для пилота, test и прогрева; точные денежные значения сохранены строками. |
| `cpu-retrieval.json`, `cpu-retrieval.jsonl.gz` | Отдельный CPU-замер первичного поиска: сводка и время каждого запроса. Это не сквозная задержка с реранжированием. |
| `manifest.json` | Контрольные суммы публичных файлов и оригиналов, обозначенных логическими именами без путей частной машины. |

`laya-multi`, `bge`, `qwen-0.6b`, `qwen-8b` и `jev-openrouter` соответствуют точным именам и ревизиям в `model-settings.json`. В каждой модели 1271 test-запрос обрабатывается дважды: по одному списку для BM25 и RRF, по 20 кандидатов. Оценки разных моделей имеют разный смысл и не калиброваны друг относительно друга.

## Проверка без API и GPU

Из корня репозитория:

```sh
python3 results/verify_public.py
```

Нужна только стандартная библиотека Python. Проверка пересчитывает SHA-256, количество и состав кандидатов, сортировку и разрешение равных оценок, средние метрики из сохраненных значений по запросам, все 30 bootstrap-интервалов, P50/P95, пики памяти, throughput и суммы стоимости. На опубликованных данных: 12 720 списков с учетом десяти прогревочных.

Для независимого пересчета метрик релевантности нужны исходные test qrels из BEIR. После получения наборов через `prepare.py`:

```sh
python3 results/verify_public.py --data-dir data/beir
```

Проверка требует совпадения SHA-256 qrels и пересчитывает 17 794 ранжирования: исходную выдачу, oracle и пять реранкеров на обоих методах поиска. Используются линейные gains, ноль для неразмеченных документов и полная разметка запроса в знаменателях. Без `--data-dir` проверяются сохраненные агрегаты, но релевантность документов не пересчитывается.

Опциональный `--charts PATH` дополнительно сверяет качество, задержку, память и throughput с `benchmark-charts.data.json`.

## Границы публикации

Публикуются основные успешные измерения пяти моделей, их прогрев, подготовленные кандидаты и перечисленные численные сводки. Пилотные оценки моделей, исходные HTTP request/response, события и журналы, неуспешная историческая throughput-попытка после сбоя CUDA, развертывание и операционные manifests не входят в этот набор. Все эти оригиналы сохранены отдельно; пропуск в публичной проекции не означает, что их не было. Основные измерения завершены без ошибок и повторов. Измерение throughput выполнено отдельно после технических пилотов на другой машине.

Не публикуются ключи, заголовки авторизации, ID запросов API, балансы и сведения аккаунтов, адреса/ID машин, UUID GPU, абсолютные локальные пути, полные корпуса и частные заметки. API-cost основан на сохраненных числах `usage`; публичный набор не содержит банковских или аккаунтных доказательств списания. Контрольная сумма оригинала фиксирует происхождение, но не заменяет доступ к самому оригиналу.

## Повторение экспорта владельцем архива

`export_public.py` использует явные списки разрешенных полей и известную структуру исторического архива. Он не загружает данные, не вызывает модели и не копирует содержимое исходных manifests/events. Выходной каталог должен отсутствовать или быть пустым:

```sh
python3 results/export_public.py --source /path/to/private-benchmark-archive --output /path/to/new-public-results
python3 results/verify_public.py --results /path/to/new-public-results --data-dir /path/to/beir
```

JSON сериализуется детерминированно; gzip не включает исходное имя файла и время экспорта. Публичные файлы, повторно полученные из тех же оригиналов той же версией Python, совпадают побайтно. Перед публикацией нового экспорта требуется просмотреть данные и проверить отсутствие частных сведений.
